# PRD: PDF 요약 웹 앱

- 문서 상태: 확정 (사용자가 PM의 제안값을 모두 제안대로 승인함)
- 표기 규칙: **[확정]** = 사용자가 직접 정한 것, **[확정(제안대로)]** = PM이 제안했고 사용자가 제안대로 승인한 것
- 이 문서는 요구사항만 다룬다. 구조, API, DB 설계와 코드는 포함하지 않는다.

---

## 1. 목표

대학생이 논문이나 강의자료 같은 긴 PDF를 올리면, AI가 핵심을 정리한 요약 화면을 보여 준다. 사용자는 이 요약을 먼저 훑고 그 PDF를 정독할지 판단한다. **[확정]**

### 성공의 모습
- 사용자가 PDF 전체를 읽지 않고도 문서의 핵심을 파악한다.
- 사용자가 "정독할 문서인가"를 짧은 시간에 결정한다.

### 전제
- AI는 OpenRouter의 무료(`:free`) 모델을 사용한다. **[확정]**
- 무료 모델이므로 응답 지연, 호출 제한, 일시적 실패가 생길 수 있다. 이 점은 아래 오류 처리 요구에 반영한다.

## 2. 사용자와 사용 상황

| 항목 | 내용 |
|---|---|
| 사용자 | 대학생 **[확정]** |
| 대상 문서 | 논문, 강의자료(텍스트가 있는 PDF) **[확정]** |
| 사용 상황 | 읽을 문서는 많고 시간은 부족할 때, 정독 전에 핵심을 빠르게 훑고 싶다 **[확정]** |
| 사용자가 얻는 것 | 한 줄 요약, 핵심 요점, 주요 키워드로 문서의 성격과 내용을 빠르게 파악 |

## 3. 기능 목록과 우선순위

우선순위: P0 = 없으면 제품이 성립하지 않음, P1 = 이번 범위에 포함되는 핵심 기능, P2 = 있으면 좋음(이번 범위의 보조 요구).

| ID | 기능 | 우선순위 | 비고 |
|---|---|---|---|
| F1 | PDF 올리기와 AI 요약 | P0 | 요약 길이 선택의 전제가 되는 기본 흐름이라 핵심 기능으로 **전제 포함**한다. 사용자가 목록에서 따로 고른 항목은 아니다. |
| F2 | 요약 길이 선택(짧게/보통/자세히) | P0 | 사용자가 꼭 필요하다고 선택한 기능 **[확정]** |
| F3 | 요약 화면 표시(한 줄 요약, 핵심 요점, 키워드) | P0 | 요약 화면에 담을 것으로 확정 **[확정]** |
| F4 | 오류 안내(업로드 불가, 요약 실패) | P1 | **[확정(제안대로)]** 안전하게 실패하기 위한 제안 |
| F5 | 개인정보·외부 전달 안내 | P1 | **[확정(제안대로)]** 사용자 보호를 위한 제안. 아래 6.4 참고 |
| F6 | 반응형·접근성 | P2 | **[확정(제안대로)]** 제안 |

## 4. 기능별 수용 기준

수용 기준은 "이 조건을 만족하면 기능이 끝났다"고 보는 기준이다.

### F1. PDF 올리기와 AI 요약 (P0)
- 사용자는 PDF 파일 하나를 선택하거나 끌어 놓아 올릴 수 있다.
- PDF가 아닌 파일은 올릴 수 없고, 이유를 알려 준다.
- 텍스트가 있는 정상 PDF를 올리면 AI 요약이 생성되어 요약 화면으로 이어진다.
- 요약이 만들어지는 동안 진행 중임을 알 수 있는 표시가 보인다.
- 요약 결과는 올린 문서의 내용에 근거한다(문서에 없는 내용을 지어내지 않는 것을 목표로 한다).

### F2. 요약 길이 선택 (P0)
- 사용자는 요약 전에 "짧게 / 보통 / 자세히" 중 하나를 고를 수 있다.
- 기본 선택값은 "보통"으로 제안한다. **[확정(제안대로)]**
- 선택한 길이에 따라 요약의 분량이 눈에 띄게 달라진다(짧게 < 보통 < 자세히).
- 길이별 구체 분량(예: 요점 개수, 글자 수)은 아래 5장 기준을 따르며, 세부 수치는 **[확정(제안대로)]**.

### F3. 요약 화면 표시 (P0)
- 요약 화면에 한 줄 요약, 핵심 요점, 주요 키워드가 모두 나온다.
- 세 항목이 구분되어 한눈에 읽힌다.
- 상세 구성은 5장을 따른다.

### F4. 오류 안내 (P1) **[확정(제안대로)]**
- 요약이 실패해도 화면이 멈추거나 빈 화면이 되지 않는다.
- 실패 원인을 사용자가 이해할 수 있는 말로 알려 주고, 다음에 할 행동(다시 시도, 다른 파일 올리기)을 안내한다.
- 오류 문구에 내부 정보(키, 서버 주소, 시스템 오류 원문)를 노출하지 않는다.

### F5. 개인정보·외부 전달 안내 (P1) **[확정(제안대로)]**
- 업로드 화면에서 "올린 PDF의 내용이 AI 처리를 위해 외부 AI 서비스로 전달된다"는 사실을 올리기 전에 알려 준다.
- 사용자가 안내를 볼 수 있는 상태에서 올리도록 한다.

### F6. 반응형·접근성 (P2) **[확정(제안대로)]**
- 노트북과 모바일 화면 폭에서 모두 깨지지 않고 사용할 수 있다.
- 키보드만으로 파일 선택, 길이 선택, 요약 시작이 가능하다.
- 글자와 배경의 대비가 충분하고, 진행 상태와 오류가 색에만 의존하지 않고 글로도 전달된다.

## 5. 요약 화면 구성(담을 것)

| 순서 | 구성 요소 | 내용 | 상태 |
|---|---|---|---|
| 1 | 한 줄 요약 | 문서 전체를 한 문장으로 설명 | **[확정]** |
| 2 | 핵심 요점 | 3~5개의 목록 | **[확정]** |
| 3 | 주요 키워드 | 문서를 대표하는 단어 목록 | **[확정]** (키워드 개수는 **[확정(제안대로)]**, 제안 5~10개) |

- 요약 길이 선택에 따라 달라지는 부분(제안): 핵심 요점은 항상 3~5개 범위 안에서 "짧게"는 적은 쪽, "자세히"는 많은 쪽이며, 각 요점 문장의 길이로도 차이를 둔다. **[확정(제안대로)]**
- 요약 화면에 별도로 표시하지 않는 것: 원문 페이지 수, 글자 수, 파일 이름(7장 참고).

## 6. 사용자가 정하지 않았지만 필요한 요구 (PM 제안, 제안대로 확정)

아래 값은 PM이 제안했고, 사용자가 제안대로 승인해 **[확정(제안대로)]**이 되었다. 구현·시험 중 실제 측정 결과에 따라 숫자는 조정할 수 있다.

### 6.1 파일 크기·쪽수 상한 **[확정(제안대로)]**
| 항목 | 제안값 | 이유 |
|---|---|---|
| 파일 크기 상한 | **4MB** (변경: 처음 제안은 10MB) | Vercel 함수의 요청 본문 한도(4.5MB)에 맞춤. 사용자가 지시해 10MB에서 변경 |
| 쪽수 상한 | 50쪽 | 긴 논문은 포함하되, 처리 시간 초과를 막기 위함 |
| 상한 초과 시 | 올리기를 막고 "파일이 너무 큽니다(최대 4MB, 50쪽)"처럼 안내 | 사용자가 원인을 알 수 있어야 함 |

### 6.1.1 긴 문서 처리 **[확정(제안대로)]**
| 항목 | 내용 |
|---|---|
| 문제 | 4MB·50쪽 PDF는 텍스트가 길어 무료 모델이 한 번에 읽지 못할 수 있다 |
| 결정 | 텍스트가 모델이 읽을 수 있는 길이를 넘으면 **앞부분만 사용해 요약**한다. 나눠서 여러 번 요약하지 않는다 |
| 이유 | 논문의 핵심(초록·서론)은 앞쪽에 몰려 있고, 호출이 한 번이라 60초 안에 끝나며 무료 모델 호출 한도에도 덜 걸린다 |
| 화면 | 앞부분만 사용했을 때 요약 화면에 "문서가 길어 앞부분을 기준으로 요약했어요"라고 알린다 |
| 수용 기준 | 긴 PDF를 올려도 요약 화면이 나오고, 앞부분만 쓰였다면 그 안내가 보인다 |

### 6.2 스캔 PDF·빈 PDF 처리 **[확정(제안대로)]**
| 경우 | 제안 동작 |
|---|---|
| 스캔 PDF(이미지만 있고 텍스트가 없음) | 이번 범위에서는 지원하지 않음. "텍스트를 읽을 수 없는 PDF입니다. 텍스트가 포함된 PDF를 올려 주세요."라고 안내 |
| 빈 PDF(내용 없음) | 요약하지 않고 "내용이 없는 PDF입니다."라고 안내 |
| 암호가 걸렸거나 손상된 PDF | 요약하지 않고 "파일을 열 수 없습니다."라고 안내 |

### 6.3 오류 안내 문구와 AI 모델 실패 시 동작 **[확정(제안대로)]**
| 상황 | 제안 동작 |
|---|---|
| AI 응답 지연(제한 시간 초과) | 중단하고 "요약이 오래 걸려 중단했습니다. 잠시 후 다시 시도해 주세요." 안내 |
| 첫 번째 모델이 응답이 없거나 오류(호출 한도 429 포함) | 사용자에게 알리지 않고 **두 번째 모델로 한 번 넘어간다**. 이 전환이 "자동 재시도 1회"이다 |
| 두 모델 모두 실패 | 대기 없이 "지금 요약 서비스가 혼잡합니다. 잠시 후 다시 시도해 주세요." 안내 |
| AI가 형식에 맞지 않는 결과를 줌 | 사용자에게 깨진 결과를 보여 주지 않고 해당 모델은 실패로 처리한다(두 번째 모델이 남아 있으면 넘어가고, 없으면 안내) |
| 자동 재시도 | 두 번째 모델로의 전환 1회가 전부이다. 같은 모델을 반복해서 부르지 않는다 |
| 모델 이름 | 첫 번째 `nvidia/nemotron-3-ultra-550b-a55b:free`, 두 번째 `nvidia/nemotron-3.5-super-vl:free` (사용자 지시) |
| 공통 | 실패 시 사용자가 같은 파일로 다시 시도할 수 있어야 함 |

### 6.4 개인정보·외부 전달 안내 **[확정(제안대로)]**
논문이나 강의자료에는 저작권이 있는 내용, 미공개 연구, 개인정보가 들어 있을 수 있다. 올린 PDF의 텍스트는 외부 AI 서비스(OpenRouter 경유)로 전달된다. 따라서 다음을 제안한다.
- 올리기 전에 "문서 내용이 외부 AI 서비스로 전달됩니다. 민감한 개인정보나 비공개 자료는 올리지 마세요."를 보여 준다.
- 올린 PDF와 요약 결과는 이번 범위에서 저장하지 않는 것을 원칙으로 제안한다(요약 저장 기능이 범위 밖이므로). 처리가 끝나면 서버에 남기지 않는다.
- API 키 등 비밀 값은 화면, 로그, 문서에 노출하지 않는다(변수 이름만 사용).
- 무료 모델 제공사가 입력 데이터를 어떻게 다루는지는 확인이 필요하다(질문 모음 참고).

### 6.5 반응형·접근성 **[확정(제안대로)]**
F6 수용 기준과 같다. 지원할 화면 폭과 접근성 수준(예: 어느 기준을 목표로 할지)은 정해지지 않았다.

## 7. 범위 밖(이번에 만들지 않음)

사용자가 이번 기능으로 고르지 않은 후보이다.

| 기능 | 뺀 이유 |
|---|---|
| 지난 요약 저장·목록 보기 | 저장 기능은 사용자 계정과 데이터 보관이 따르며, 이번 핵심(한 번 올려 요약 확인)에 필수가 아님 |
| 구글 로그인 | 저장 기능이 없으면 로그인이 필요 없고, 핵심 흐름에 필수가 아님 |
| 원문 대비 정보(페이지 수·글자 수)와 파일 이름 표시 | 요약 내용을 파악하는 데 필수가 아니라서 사용자가 이번에 고르지 않음 |
| 요약 복사·다시 요약하기 버튼 | 편의 기능이며 핵심 흐름에 필수가 아님. 단, 길이를 바꿔 다시 요약하려면 새로 올려야 함 |

참고: 이번 범위는 로그인 없이 쓰고 결과를 저장하지 않는 구조를 가정한다(8장 가정 참고).

## 8. 완료 기준

**[확정]** 정상 PDF(텍스트가 있는 파일)를 올리면 제한 시간 안에 요약 화면(한 줄 요약, 핵심 요점, 키워드)이 나온다.

| 항목 | 값 | 상태 |
|---|---|---|
| 제한 시간 | 올린 뒤 60초 이내 | **[확정(제안대로)]** 제안값. 무료 모델의 속도 편차를 고려한 숫자이며 실제 측정 후 조정이 필요 |
| 검증 대상 | 텍스트가 있는 정상 PDF | **[확정]** |
| 확인할 결과 | 한 줄 요약, 핵심 요점(3~5개), 키워드가 모두 표시됨 | **[확정]** |
| 길이 선택 | 짧게/보통/자세히 각각에서 위 결과가 나오고 분량 차이가 확인됨 | 확정(분량 수치는 제안대로 확정) |

## 9. 가정한 것

- 로그인 없이 누구나 쓰며, 요약 결과는 저장하지 않는다(범위 밖 항목에서 도출).
- 한 번에 PDF 한 개만 처리한다.
- 요약 언어는 한국어를 기본으로 한다(Q4 제안대로 확정). 영어 논문도 한국어로 요약한다. 사용자가 요약 언어를 고르는 기능은 이번 범위 밖이다.
- 사용자 환경은 일반적인 웹 브라우저이다.

## 10. 질문 모음과 결정

Q1~Q15는 모두 아래 '제안'대로 확정했다. 단 Q11은 결정이 아니라 **구현 전에 해야 할 확인 일**이다(무료 모델 제공사의 데이터 이용 정책을 확인해 안내 문구에 반영).
Q4는 제안이 "기본: 한국어 요약"이었고, 그 기본대로 한국어 요약으로 확정했다.

| 번호 | 질문 | 제안 |
|---|---|---|
| Q1 | 완료 기준의 제한 시간은 몇 초로 할까? | 60초 |
